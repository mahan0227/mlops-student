Lab And Demo: Introduction to MLOps

Everything in this guide runs in a web browser. You do not install Python, Docker, Git, or Jenkins. You need:

  • a free GitHub account
  • a modern browser
  • optional for the last checkpoints: a free Killercoda login (sign in with GitHub or Google)

The starter code lives at:

https://github.com/mahan0227/mlops-student

The online workflow students paste is in this bundle:

online-lab/mlops-online.yml

Part A: Instructor Demo Runbook

Demo goal

Show one complete ML lifecycle in the browser: fork, generate data, drop PII, train, publish a container to GHCR, call /predict in Killercoda, then roll back to a previous tag.

Before the session

  1. Fork the student repo on a demo account and replace the workflow with online-lab/mlops-online.yml.
  2. Confirm the Actions run is green and the GHCR package is public.
  3. Sign in to Killercoda and open the Docker playground once so the login is cached.
  4. Confirm demo-walkthrough.mp4 opens in demo-player.html.
  5. Open walkthrough-guide.html in a second tab.

Play the recording first

Play demo-walkthrough.mp4 full screen before anyone types. Pause a chapter while the room catches up. Students repeat the same browser steps. The written steps below match the video.

Demo steps (about 16 minutes)

  1. Open the public starter repo. Press . to show github.dev. Nobody installed an editor.
  2. Show src/data_prep.py dropping email, phone, and customer_id.
  3. Show .github/workflows/mlops-online.yml after it has been replaced by the online workflow.
  4. Open Actions. Walk generate → PII printout → clean columns → train → tests → push to GHCR.
  5. Download or expand the model-bundle artifact and open metrics.json.
  6. Open the package page. Show the latest tag and the run- tag.
  7. In Killercoda, pull the image, run it, and curl /health, /version, and /predict.
  8. Pull the previous run- tag and show /version change. That is rollback.

Talking points

  • PII never reaches the model. The log proves it.
  • The version string is the contract between training and serving.
  • Tests are the gate before the image is published.
  • Rollback is a previous tag, not a rewrite.

Fallback

If GitHub or Killercoda fails, stay on the recording. Play with Docker is the terminal fallback.

Part B: Guided Lab for Students

Lab title

From a public fork to a live /predict API, with nothing installed

Objective

Fork the student workshop repo, run the lifecycle on GitHub Actions, publish the image, and prove the API in a browser terminal.

Lab map and checkpoints

Checkpoint You will Success signal
1 Fork the starter repo as public Your copy exists under your username
2 Paste the online workflow and commit Actions tab shows a run starting
3 Read the PII and clean-column logs Raw has email; clean does not
4 Read a green run and the artifacts Tests green; metrics.json visible
5 Make the GHCR package public Package visibility is Public
6 Pull and call /predict in Killercoda JSON with prediction and probability
7 Pull the previous tag /version matches the older run

Work in pairs if you like, but each person must commit at least once.

Checkpoint 1: Fork the starter repository

  1. Sign in at github.com.
  2. Open https://github.com/mahan0227/mlops-student
  3. Click Fork. Keep it Public. Do not tick extra branches unless you want them.
  4. Click Create fork.

Success signal: the browser shows YOUR_USER/mlops-student.

Checkpoint 2: Paste the online workflow

The starter repo can train on a laptop. Today we replace the workflow so GitHub does the work.

  1. On your fork, press . (the period key). github.dev opens.
  2. Open .github/workflows/mlops-online.yml.
  3. Select all and replace it with the file from online-lab/mlops-online.yml in this bundle (also pasted in walkthrough-guide.html).
  4. Open Source Control. Commit message: Run the MLOps lifecycle on GitHub Actions. Click Commit & Push.
  5. If GitHub asks you to enable Actions on the fork, click I understand my workflows, go ahead and enable them, then re-run the workflow from the Actions tab.

Success signal: the Actions tab shows a run named mlops-online.

Checkpoint 3: Read the PII checkpoint in the logs

  1. Open the run. Click the mlops job.
  2. Open Generate synthetic data. Find RAW COLUMNS and the three email rows.
  3. Open Data prep (drop PII). Find CLEAN COLUMNS and the line PII columns are gone.

Success signal: you can point to email in the raw log and its absence in the clean log.

Checkpoint 4: Read the green run and the model bundle

  1. Confirm Unit tests is green. That is the quality gate.
  2. Confirm Build and push image is green.
  3. In the run summary, download the model-bundle artifact and open metrics.json and metadata.json.

Success signal: you can say the version and the roc_auc out loud.

Checkpoint 5: Make the package public

  1. On the repository page, click Packages.
  2. Open the image. Click Package settings.
  3. Under Danger Zone, change visibility to Public.

If you skip this, Killercoda will say pull access denied.

Success signal: a visitor who is not logged in can see the package.

Checkpoint 6: Call the API in Killercoda

  1. Open https://killercoda.com/playgrounds/scenario/docker and start the scenario. Sign in with GitHub if asked.
  2. Replace YOUR_USER with your GitHub username, in lowercase:
docker pull ghcr.io/YOUR_USER/mlops-student:latest
docker run -d -p 8000:8000 --name ml-prod ghcr.io/YOUR_USER/mlops-student:latest
curl -s http://localhost:8000/health
curl -s http://localhost:8000/version
curl -s -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"transaction_id":"tx_000000","age":42,"country":"US","device_type":"mobile","transaction_amount":250.5,"hour_of_day":13,"num_prev_txns":3,"is_international":0}'

Success signal: JSON with model_version, prediction, and probability.

If Killercoda is full, use https://labs.play-with-docker.com and the same commands.

Checkpoint 7: Roll back to a previous tag

After a second green run you will have latest plus two run- tags.

docker pull ghcr.io/YOUR_USER/mlops-student:run-PREVIOUS_ID
docker rm -f ml-prod
docker run -d -p 8000:8000 --name ml-prod ghcr.io/YOUR_USER/mlops-student:run-PREVIOUS_ID
curl -s http://localhost:8000/version

Success signal: model_version matches the older run, not the newest one.

To create the second run without changing code, open Actions → mlops-online → Run workflow.

Troubleshooting

Symptom Likely cause Fix
Actions tab is empty Workflows disabled on the fork Enable Actions, then Run workflow
YAML error at the start Indentation or tabs Re-paste the file from the guide
Red at Unit tests Training or schema failed Read the first red step, not the last
denied when pushing the image Package write permission Confirm the workflow permissions: packages: write
pull access denied in Killercoda Package is still private Package settings → Public
400 Missing feature fields Predict payload incomplete Copy the payload from this guide
Killercoda will not start Session or login Sign in with GitHub, or use Play with Docker

Cleanup

Nothing is installed on the laptop. You may delete the Killercoda session. Keep the fork.
